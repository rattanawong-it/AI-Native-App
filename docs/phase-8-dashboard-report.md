## 3. การตัดสินใจเชิงออกแบบ

### 3.1 Export PDF ใช้การพิมพ์ผ่านเบราว์เซอร์ ไม่เพิ่ม dependency

spec §9 เสนอ `@react-pdf/renderer` หรือ `puppeteer` ไว้ แต่ทั้งคู่มีราคาที่ต้องจ่าย —
`@react-pdf/renderer` ต้อง embed ฟอนต์ไทยเองและเขียน layout ใหม่ทั้งหมด (กราฟ `recharts` แสดงไม่ได้)
ส่วน `puppeteer` ทำให้ Docker image โตขึ้นหลายร้อย MB และต้องจัดการ auth cookie ตอนยิงหน้าเว็บเอง

เลือกทำ print stylesheet + ปุ่ม "พิมพ์ / บันทึก PDF" ให้ผู้ใช้กด Save as PDF ของเบราว์เซอร์แทน
ได้ผลลัพธ์ที่ฟอนต์ไทยและกราฟตรงกับที่เห็นบนจอ 100% โดยไม่เพิ่ม dependency เลย

**ข้อจำกัดที่ต้องรู้:** ไม่มี API ฝั่ง server สำหรับสร้าง PDF อัตโนมัติ ถ้าวันหนึ่งต้องส่งรายงาน
เข้าอีเมลผู้บริหารเองทุกสิ้นเดือน ต้องกลับมาคุยเรื่องนี้ใหม่

> กติกาการพิมพ์อยู่ใน `<style>` ของ `SummaryReportContent.tsx` — layout หลักตั้ง `h-screen`
> กับ `overflow` ไว้ ต้องคลายออกก่อน ไม่งั้นเบราว์เซอร์จะพิมพ์ได้แค่หน้าแรกหน้าเดียว

### 3.2 รายงานเป็นเอกสารหน้าเดียว ไม่ใช้แท็บ

หน้ารายงานสรุปเรียงทุกส่วนต่อกันลงมา เพราะปลายทางคือเอกสารที่ต้องส่งผู้บริหาร
ถ้าใช้แท็บ ผู้ใช้จะกดพิมพ์แล้วได้แค่แท็บที่เปิดอยู่ ต้องพิมพ์ทีละแท็บแล้วเอามาต่อกันเอง

### 3.3 "ค้าง" คิดย้อนเวลาได้จริง ไม่ได้ดูสถานะปัจจุบัน

จำนวนใบที่ค้างนับจาก "แจ้งก่อนสิ้นช่วง และ ณ เวลานั้นยังไม่ `resolvedAt` / `closedAt`"
ไม่ได้นับจาก `status` ปัจจุบัน — เปิดรายงานเดือนสิงหาคมย้อนหลังในเดือนธันวาคม
ตัวเลขจึงยังเป็นตัวเลขของเดือนสิงหาคม ไม่ใช่ของวันที่เปิดดู

ด้วยเหตุผลเดียวกัน "รับเข้า / แก้ไขแล้ว / ปิดงาน" เป็นคนละชุดใบกัน — ใบที่ปิดเดือนนี้
อาจแจ้งมาตั้งแต่เดือนก่อน ตัวเลขสามตัวนี้จึงไม่ต้องบวกกันได้พอดี

### 3.4 แดชบอร์ดกับรายงานใช้ตัวคำนวณตัวเดียวกัน

`dashboard-service.ts` เรียก `buildTrend()` และ `tallySla()` จาก `report-service.ts`
และ widget งานวันนี้/เลยกำหนดเรียก `loadWorkItems()` ตัวเดียวกับหน้า My Work
ถ้านิยาม "เลยกำหนด" หรือ "% SLA" เปลี่ยน จะเปลี่ยนที่เดียวแล้วตรงกันทุกหน้า

### 3.5 ลำดับสีของกราฟ — ไม่ได้ไล่ตาม `--chart-1..5`

ตรวจ palette ของ design system ด้วยเครื่องมือวัดแล้วพบว่า `--chart-1` (น้ำเงิน `#2563eb`)
กับ `--chart-2` (ม่วง `#7d5fd1`) ต่างกันน้อยเกินไป — ΔE 11.0 สำหรับคนตาปกติ และ 4.1
สำหรับคนตาบอดสีแบบ protan ซึ่งต่ำกว่าเกณฑ์ทั้งคู่ ถ้าใช้เป็นสองสีแรกของกราฟ
คนอ่านจะแยกสองเส้น/สองแท่งแรกไม่ออก

จึงกำหนดลำดับเป็น **1 → 3 → 4 → 5 → 2** ซึ่งผ่านเกณฑ์ครบทุกข้อ (ช่วงความสว่าง,
ความอิ่มสี, การแยกสีของคนตาบอดสี, คอนทราสต์กับพื้น) โดย**ไม่ต้องแก้ token ใน `globals.css`**
ส่วนมิติที่มีสีประจำตัวอยู่แล้ว (ความสำคัญ, สถานะ) ใช้สีของมันเองให้ตรงกับ Badge ทั้งระบบ

จำนวนใบกับ % SLA แยกเป็นสองกราฟ ไม่ทำกราฟสองแกน Y เพราะสองแกนทำให้เทียบความชันกันได้ผิด

### 3.7 ค้นหารวมเป็นคนละเส้นกับ RAG

`POST /api/search` เดิมเป็นการค้นเชิงความหมายในคลังเอกสาร RAG (pgvector) จึงไม่แตะ
สร้าง `GET /api/search/global` แยกสำหรับค้นข้อความตรงๆ ข้ามตารางงาน
สิทธิ์แยกรายแหล่ง — แหล่งที่ผู้ใช้ไม่มีสิทธิ์จะไม่ถูก query เลย ไม่ใช่ query แล้วค่อยกรองทีหลัง

### 3.8 บั๊กที่เจอตอนทดสอบด้วยบัญชีจริง — spread เขียนทับตัวกรองขอบเขต

ตอนทดสอบด้วยบัญชี role `user` พบว่าส่วน "ภาระงานเจ้าหน้าที่" ของรายงานคืนมา 3 คน
ทั้งที่ควรเห็นเฉพาะของตัวเอง สาเหตุคือใน `buildWorkloadSection()` เขียนว่า

```ts
where: { ...base, assigneeId: { not: null }, createdAt: {...} }
```

`base` คือ `{ assigneeId: <ตัวเอง> }` เมื่อ scope เป็น `own` แต่ `assigneeId: { not: null }`
ที่เขียนต่อท้ายไป**ทับ**คีย์เดิมทิ้ง ตัวกรองขอบเขตจึงหายไปเงียบๆ โดยที่ TypeScript ไม่เตือน
เพราะทั้งสองค่าเป็น `TicketWhereInput["assigneeId"]` ที่ถูกต้องทั้งคู่ — เป็นการรั่วของ NFR3

แก้โดยสร้างเงื่อนไขเดียวที่ครอบทั้งสองกรณีแทนการ spread แล้วเขียนทับ

```ts
const scopedAssignee: Prisma.TicketWhereInput =
    scope.kind === "all" ? { assigneeId: { not: null } } : { assigneeId: scope.userId }
```

ตรวจจุดอื่นที่ spread แล้วเขียนคีย์ต่อท้ายทั้งไฟล์แล้ว — ที่เหลือไม่มีคีย์ชนกัน

## 5. ของค้าง

1. **ปุ่ม "พิมพ์ / บันทึก PDF" ยังไม่ได้กดทดสอบ** — `window.print()` เปิด modal ของเบราว์เซอร์
   ซึ่งทำให้เครื่องมืออัตโนมัติค้าง จึงเว้นไว้ให้กดด้วยมือ · สิ่งที่ต้องดูคือได้ครบทั้งฉบับ
   ไม่ใช่แค่หน้าแรก และแถบเมนูซ้ายกับปุ่มต่างๆ ต้องไม่ติดไปในกระดาษ
2. **F7.13 / F1.7 ไฟล์แนบ** — ยังเลื่อนอยู่ รอสรุปว่าจะเก็บไฟล์ที่ไหน (local `UPLOAD_DIR` / S3 / Vercel Blob)
3. **`app/(main)/dashboard/SignOutButton.tsx` ไม่มีใครเรียกใช้** — เป็นไฟล์ค้างมาตั้งแต่ commit แรก
   ของโปรเจกต์ (ไม่ได้เกิดจากเฟสนี้ ตรวจแล้วว่าแดชบอร์ดเดิมก็ไม่ได้ import) ถ้าจะลบต้องเปิดเป็นงานแยก
4. **Snapshot ยังลบไม่ได้** — บันทึกซ้ำช่วงเดิมจะแทนที่ของเดิมให้ แต่ยังไม่มีปุ่มลบทิ้ง
   ถ้าบันทึกผิดช่วงต้องบันทึกทับ ยังไม่มีใน F7.23 จึงไม่ได้ทำ
5. **โหมดมืดของกราฟ** — token `--chart-*` ชุดโหมดมืดผ่านเกณฑ์คอนทราสต์และการแยกสีของ
   คนตาบอดสีแล้ว แต่ความสว่างสูงกว่าช่วงที่แนะนำเล็กน้อย (L 0.71–0.84 เทียบช่วง 0.48–0.67)
   ผลคือเส้นกราฟบนพื้นมืดจะดูสว่างกว่าที่ควรนิดหน่อย ไม่ถึงกับอ่านไม่ออก
   **ไม่ได้แก้เพราะต้องแตะ `globals.css` ซึ่งอยู่นอกขอบเขตที่อนุมัติไว้** — ถ้าจะปรับ ต้องเปิดเป็นงานแยก
6. **`Task` ไม่มีคอลัมน์ "ปิดงานเมื่อไร"** — ตัวเลข "Task ที่ปิดได้ในช่วงนี้" ใช้ `updatedAt`
   ของใบที่สถานะเป็น `done` เป็นตัวแทน ใบที่ถูกแก้อย่างอื่นหลังปิดงานจะถูกนับเข้าช่วงที่แก้ล่าสุด
   เช่นเดียวกับคำขออนุมัติที่ใช้ `updatedAt` แทนเวลาตัดสิน — ถ้าต้องการความแม่นยำกว่านี้
   ต้องเพิ่มคอลัมน์ `completedAt` / `decidedAt` ซึ่งเป็นการแก้ schema
