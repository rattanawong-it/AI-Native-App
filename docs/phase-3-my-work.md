## 4. การตัดสินใจเชิงออกแบบ

| # | เรื่อง | เหตุผล |
|---|---|---|
| 1 | **My Work เป็น union ฝั่งแอป ไม่ใช่ SQL UNION** | สามตารางมีคอลัมน์คนละชุด · เป็น "งานของคนเดียว" ปริมาณอยู่หลักสิบ จึงเรียงในหน่วยความจำได้ปลอดภัย (เพดาน 200 แถวต่อประเภท) |
| 2 | **สรุปชั่วโมงใช้ `groupBy` ของ Prisma** | ต่างจากรายงาน SLA ที่ต้องตัดสินผลรายใบก่อนจึงรวมได้ · การรวมชั่วโมงเป็นการบวกเลขล้วน ฐานข้อมูลทำให้ได้ จึงไม่มีเพดานจำนวนแถวที่นี่ |
| 3 | **นับ "เลยกำหนด/ครบกำหนดวันนี้" จากชุดงานเต็มก่อนกรอง** | ตัวเลขบนแท็บจะได้ไม่เปลี่ยนไปมาตามแท็บที่ผู้ใช้เลือกอยู่ |
| 4 | **งานส่วนตัวไม่มีใครเห็นของใคร แม้แต่ admin** | เป็นบันทึกส่วนตัว ไม่ใช่ข้อมูลของหน่วยงาน · ทุก query ผูก `ownerId = me` (NFR3) |
| 5 | **หัวหน้า "ดู" บันทึกเวลาของทีมได้ แต่แก้แทนไม่ได้** | บันทึกเวลาเป็นคำให้การของเจ้าตัวเรื่องภาระงาน |
| 6 | **ลบงานส่วนตัวที่มีบันทึกเวลาผูกอยู่ไม่ได้** | `WorkLog.todoId` ไม่ได้ตั้ง cascade โดยตั้งใจ — บันทึกเวลาเป็นหลักฐานภาระงาน ไม่ควรหายไปพร้อมการลบงาน |
| 7 | **F3.6 นับรวมบันทึกเวลาที่เคยลงไว้กับใบนั้นแล้ว** | เจ้าหน้าที่บางคนลงเวลาระหว่างทำงาน ไม่ได้รอลงตอนปิด · ถ้าบังคับกรอกซ้ำตอนปิดจะได้ตัวเลขซ้ำซ้อน |
| 8 | **`api/settings` จำกัดเฉพาะคีย์ใน allowlist** | คีย์อื่นใน `AppSetting` (ชนิดไฟล์แนบ, ช่องทางแจ้งเตือน) ยังไม่มีหน้าจอรองรับ ไม่ควรเปิดให้เขียนทับ |
| 9 | **`refType` เปลี่ยนเมื่อไร ต้องล้าง id ของประเภทเดิมพร้อมกัน** | กันข้อมูลกำพร้าที่รายงานภาระงานจะอ่านไม่ออก · ตรวจสองชั้น (zod + ตรวจกับ DB จริง) |
| 10 | **หน้ารายงานภาระงานเข้าผ่านหน้ารวมรายงาน** | เลี่ยงการแตะ `sidebar-data.ts` (M5) และให้ Phase 8 มาต่อยอดตรงจุดเดียว |

## 6. ค้างไว้ / ต้องทำต่อ

1. ✅ **แก้ความเข้าใจผิดจากเอกสาร Phase 2 §6 ข้อ 1 — "dev server พัง เมนู admin หายไป" ไม่ใช่บั๊กของ worker**

   สาเหตุจริงคือ **พอร์ต**: `.env.production` ตั้ง `NEXT_PUBLIC_BETTER_AUTH_URL="http://localhost:8810"`
   เมื่อรันเซิร์ฟเวอร์ที่พอร์ตอื่น (เช่น 3100 ที่ Phase 2 ใช้ทดสอบ) `useSession()` ฝั่ง client
   จะยิงไปที่ **:8810** ซึ่งไม่มีอะไรรับ → ไม่ได้ session → `sidebar.tsx` ตกไปใช้ role `"user"`
   เมนู "ตั้งค่าบริการ / บริหารจัดการ / ผู้ดูแลระบบ" จึงหายไปทั้งที่ล็อกอินเป็น admin
   ฝั่ง server ยังเห็น session ถูกต้องเสมอ API จึงตอบปกติ — ตรงกับอาการที่บันทึกไว้ทุกข้อ

   **ยืนยันแล้ว:** รัน build เดียวกันที่พอร์ต 8810 → sidebar แสดงครบทุกหมวด avatar ขึ้นปกติ
   **สิ่งที่ต้องทำ:** ทดสอบ production build ต้องรันที่พอร์ต **8810** เท่านั้น
   (หรือแก้ `NEXT_PUBLIC_BETTER_AUTH_URL` ให้ตรงกับพอร์ตที่ใช้จริง)

2. **`api/my-work` เรียงในหน่วยความจำ เพดาน 200 แถวต่อประเภท** — พอสำหรับ "งานของคนเดียว"
   ถ้าวันหนึ่งเจ้าหน้าที่คนเดียวถือ Ticket เกิน 200 ใบพร้อมกัน ต้องเปลี่ยนไปทำ pagination ฝั่ง DB

3. **ยังไม่มีการส่งออก Time Log เป็นไฟล์** — รายงานภาระงานดูได้บนหน้าจออย่างเดียว
   (`api/reports/export` อยู่ในเฟส 8)

4. **F3.9 Widget บน Dashboard** — เลื่อนไป Phase 8 ตามที่ตกลง (M8)

5. **`TimeLogPanel` โหลดตัวเลือกงานจาก `state=open` เท่านั้น** — แก้บันทึกเวลาเก่าที่ผูกกับงานซึ่ง
   ปิดไปแล้ว จะไม่เห็นงานนั้นในรายการ (หน้าจอขึ้นข้อความเตือนให้เลือกงานใหม่หรือเปลี่ยนเป็น "งานอื่นๆ")
   ยังไม่ได้ทำช่องค้นหางานที่ปิดไปแล้ว

6. **ของค้างจาก Phase 1–2 ที่ยังไม่ได้แตะในเฟสนี้**
   - F1.7 ไฟล์แนบ Ticket — ยังต้องตัดสินใจว่าจะเก็บไฟล์ที่ไหน
   - F1.9 รับแจ้งผ่าน LINE — เลื่อนไป Phase 4

   - ยังไม่ได้ทดสอบด้วย role `student` / `user` / `agent` / `manager` — ทั้งเฟสทดสอบด้วย admin
   - `pnpm lint` ทั้งโปรเจกต์ยังมี 18 error เดิมในไฟล์กลุ่ม "ไม่แตะเลย"
   - โลโก้/ชื่อแอปใน sidebar ยังเป็น "AI Native"
