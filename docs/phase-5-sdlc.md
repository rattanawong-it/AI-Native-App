## 4. การตัดสินใจเชิงออกแบบ

1. **การลากส่งไป "การ์ดที่จะแทรกก่อนหน้า" ไม่ใช่เลขลำดับ** — ถ้าให้หน้าจอคำนวณ `sortOrder`
   เองแล้วส่งมา เลขจะชนกันทันทีที่มีสองคนลากพร้อมกัน เซิร์ฟเวอร์จึงเป็นผู้คิดเลขให้
   โดยแทรกค่ากึ่งกลาง และจัดเลขคอลัมน์ใหม่ให้เองเมื่อช่องว่างหมด

2. **หนึ่งโครงการมี Sprint ที่ "กำลังดำเนินการ" ได้ทีละรอบเดียว** — กันงานถูกกระจายข้ามรอบ
   จนติดตามไม่ได้ · ต้องปิดรอบเดิมก่อนจึงเปิดรอบใหม่ได้ (ทั้งตอนสร้างและตอนแก้)

3. **ลบ Sprint แล้วงานไม่หายตาม** — งานถูกโยนกลับ Backlog พร้อมรายงานจำนวนใน toast

4. **งานที่มีบันทึกเวลาผูกอยู่ลบไม่ได้** — ทั้งระดับงานเดี่ยวและระดับโครงการ
   เพราะบันทึกเวลาเป็นหลักฐานภาระงานของเฟส 3 ต้องไม่หายไปพร้อมการลบ

5. **ทีมที่ถูกอ้างถึงอยู่ลบไม่ได้** — ให้ปิดใช้งานแทน เพราะทีมชุดนี้คือทีมเดียวกับที่ Ticket
   หมวดหมู่บริการ และโครงการอ้างถึง การลบจะทำให้ประวัติงานเก่าขาด

6. **หัวหน้าทีมกับบทบาทในตารางสมาชิกถูกทำให้ตรงกันเสมอ** — ไม่ว่าจะแก้จากฟอร์มทีม
   จากการเพิ่มสมาชิก หรือจากการสลับบทบาท เพื่อไม่ให้สองที่ขัดกัน

7. **การ์ดไม่มีหน้าของตัวเอง** — ใช้ `?task=<id>` บนหน้ากระดานแทน ลิงก์เดียวกันนี้ถูกใช้ทั้งใน
   การแจ้งเตือน `task_assigned`, หน้า My Work และการ์ด "งานพัฒนาที่เกี่ยวข้อง" ในหน้า Ticket

8. **Ticket หนึ่งใบแปลงได้ครั้งเดียว** — `Ticket.convertedTaskId` เป็น `@unique` อยู่แล้ว
   และการแปลงซ้ำจะทำให้ทีมพัฒนามีการ์ดซ้ำโดยไม่มีใครรู้ว่าใบไหนคือใบจริง

9. **สิทธิ์ตาม spec §7** — เจ้าหน้าที่อ่านได้ทั้งหมดและแก้/ลากได้เฉพาะงานที่ตัวเองถือ
   ส่วนการสร้าง/ลบโครงการ Sprint ทีม และการมอบหมายงานให้ผู้อื่น สงวนไว้ให้หัวหน้าขึ้นไป

## 6. ค้างไว้ / ต้องทำต่อ

### 6.1 ของเฟสนี้เอง

1. **F5.12 ยังไม่มีกราฟ burndown จริง** — ที่ทำคือสรุปจำนวนงานแยกตามคอลัมน์
   และชั่วโมงที่ประมาณ (ปิดแล้ว/ทั้งหมด) ต่อรอบ ซึ่งเป็นทางเลือกที่ระบุไว้ในหัวข้อ checklist
   ส่วนกราฟเส้นตามวันต้องเก็บ snapshot รายวัน — ยังไม่มีตารางเก็บ ควรทำพร้อม `ReportSnapshot`
   ในเฟส 8

2. **การลากใน Backlog view ยังจำกัดอยู่ที่คอลัมน์** — ลากการ์ดจาก Backlog เข้ารอบพัฒนา
   ต้องเปิดการ์ดแล้วเลือกรอบในฟอร์ม (API `move` รองรับ `sprintId` แล้ว แต่หน้าจอยังไม่มี
   ที่วางแบบลากข้ามรอบ)

3. **ยังไม่มีหน้ารายการงานข้ามโครงการ** — `GET /api/tasks` รองรับแล้ว แต่ยังไม่มีหน้าจอ
   ที่เรียกใช้ นอกจากผ่าน My Work

4. **การเรียงใหม่ทั้งคอลัมน์เมื่อช่องว่างหมด** ทำงานถูกต้องแต่ยังไม่เคยถูกกระตุ้นจริงในการทดสอบ
   (ต้องลากสลับกันหลายสิบครั้งจนตัวเลขติดกัน) — โค้ดครอบคลุมไว้แล้วแต่ยังไม่มีหลักฐานหน้างาน

5. **ยังไม่ได้ทดสอบด้วย role `agent`** — กติกา "แก้/ลากได้เฉพาะงานของตัวเอง" ตรวจแล้วในโค้ด
   ทั้งฝั่ง API และหน้าจอ แต่ระบบยังไม่มีบัญชี agent จริงให้ทดสอบ (ผู้ใช้ทั้ง 3 คนเป็น admin)

6. **`estimateHours` ที่ประมาณไว้ยังไม่ถูกเทียบกับชั่วโมงที่ลงจริง** — `WorkLog` ผูกกับ `Task`
   ได้อยู่แล้วตั้งแต่เฟส 3 แต่หน้ากระดานยังไม่แสดงชั่วโมงที่ลงจริงเทียบกับที่ประมาณ

### 6.2 ของค้างจากเฟสก่อนที่ยังไม่ได้แตะ

- F1.7 ไฟล์แนบ Ticket — ยังต้องตัดสินใจว่าจะเก็บไฟล์ที่ไหน
- F3.9 Widget บน Dashboard — เลื่อนไป Phase 8 (M8)
- `approval_requested` / `approval_decided` ยังรอ API ของเฟส 7
- กระดิ่งแจ้งเตือนยังใช้ polling 60 วินาที และยังไม่มีหน้ารวมการแจ้งเตือนทั้งหมด
- ยังไม่มีการล้าง `Notification` / `NotificationDelivery` ที่เก่ากว่า 90 วัน
- ยังไม่มีเจ้าหน้าที่จริงในระบบ → `ServiceCategory.defaultAssigneeId` ยังว่างทุกหมวด
- `pnpm lint` ทั้งโปรเจกต์ยังมี error เดิมในไฟล์กลุ่ม "ไม่แตะเลย"
- โลโก้/ชื่อแอปใน sidebar ยังเป็น "AI Native"
