## 4. การตัดสินใจเชิงออกแบบที่ควรรู้

| # | เรื่อง | ที่ทำและเหตุผล |
|---|---|---|
| 1 | **ไม่เชื่อธง `responseBreached` / `resolutionBreached` ในรายงาน** | ธงถูกตั้งตอน "อ่านรายการ" เท่านั้น (`syncBreachFlags`) ใบที่ตอบกลับช้าแต่ไม่มีใครเปิดหน้ารายการในช่วงนั้น ธงจะยังเป็น `false` · รายงานและฟิลเตอร์จึงคำนวณจากเวลาจริงทุกครั้ง ผ่าน `evaluateTicketSla()` / `breachWhere()` ใน `lib/sla-service.ts` — ธงในตารางยังคงอยู่เพื่อใช้แสดงผลย้อนหลังของใบที่ปิดแล้ว |
| 2 | **นับ % จากเฉพาะใบที่ "รู้ผลแล้ว"** | ใบที่ยังอยู่ในกำหนดและยังไม่ทำ ถือว่ายังไม่รู้ผล จึงไม่เข้าตัวหาร — ไม่งั้น % จะแกว่งตามเวลาที่เปิดดูรายงาน · ทุกตัวเลขจึงแสดงคู่กับ `(ทำทัน/ที่รู้ผลแล้ว)` ให้ตรวจสอบได้ |
| 3 | **แก้บั๊กช่วงวันที่ของหน้ารายการ (ของค้างจาก Phase 1)** | เดิมใช้ `new Date("2026-09-01")` ซึ่งเป็นเที่ยงคืน **UTC** = 07:00 น. ของไทย ทำให้ Ticket ที่แจ้งช่วง 00:00–07:00 ของวันแรกหลุดออกจากผลลัพธ์ · แก้เป็นคิดตามปฏิทินไทย (`+07:00`) ทั้ง `from` และ `to` ให้ตรงกับรายงาน |
| 4 | **F4.11 ใช้ API รายการเดิม ไม่สร้างเส้นทางใหม่** | เพิ่มแค่ฟิลเตอร์ `breached` ใน `api/tickets` จึงได้ pagination, การจัดเรียง, row-level scope ตาม role และ **ส่งออก Excel** (`api/tickets/export`) มาใช้ซ้ำทั้งชุดโดยไม่เขียนใหม่ |
| 5 | **เทียบสองคอลัมน์ในแถวเดียวกัน** | เงื่อนไข "ตอบกลับช้ากว่ากำหนด" ต้องเทียบ `respondedAt > responseDueAt` — ใช้ field reference ของ Prisma (`prisma.ticket.fields.responseDueAt`) แทนการดึงมากรองในหน่วยความจำ |
| 6 | **ล้าง cache ปฏิทินหลังบันทึกทุกครั้ง** | `lib/business-hours.ts` cache ปฏิทินไว้ 5 นาที · ทุกเส้นที่เขียน `BusinessHour` / `Holiday` เรียก `invalidateBusinessCalendar()` ไม่งั้น Ticket ที่แจ้งเข้ามาภายใน 5 นาทีถัดไปจะยังใช้ปฏิทินเดิม |
| 7 | **ลบนโยบาย SLA ได้จริง (ไม่ soft delete)** | ต่างจาก Service Catalog เพราะ `Ticket` ไม่มี FK มาที่ `SlaPolicy` — ใบเดิมเก็บ `responseDueAt` / `resolutionDueAt` ไว้ในแถวของตัวเองแล้ว การลบนโยบายจึงไม่กระทบประวัติ |
| 8 | **ตรวจนโยบายซ้ำเอง ไม่พึ่ง unique constraint** | `@@unique([priority, categoryId])` ใช้ไม่ได้กับนโยบายรวมที่ `categoryId` เป็น `null` เพราะ Postgres ถือว่า NULL แต่ละแถวต่างกัน (ปัญหาเดียวกับที่ `seed.ts` เจอ) |
| 9 | **นำเข้าวันหยุดเป็นข้อความ ไม่ใช่ไฟล์** | หนึ่งบรรทัดต่อหนึ่งวัน `MM-DD ชื่อวัน` หรือ `YYYY-MM-DD ชื่อวัน` · กล่องถูกเติมชุดวันหยุดตายตัว 15 วันไว้ให้แก้ต่อ · ตรงกับงานจริงคือคัดลอกจากประกาศสำนักนายกรัฐมนตรีมาวาง ไม่ต้องทำไฟล์กลาง |
| 10 | **หน้า `management/reports`** | เมนู "รายงาน" ใน sidebar ชี้มาที่นี่ตั้งแต่ Phase 0 แต่ยังไม่มีหน้า (404) · เฟสนี้ทำเป็นหน้ารวมรายการรายงาน เพื่อไม่ต้องแตะ `sidebar-data.ts` และให้เฟส 8 มาต่อยอดได้ |
| 11 | **แก้ toast ของหน้า admin ที่ไม่เคยแสดงผล** | `admin/catalog` (Phase 1) เรียก `toast` อยู่แล้วแต่กลุ่มหน้า admin ไม่มี `<Toaster />` ข้อความจึงไม่เคยขึ้นเลย · เพิ่ม `app/(main)/admin/layout.tsx` แก้ให้ทั้ง catalog, sla, calendar พร้อมกัน |
